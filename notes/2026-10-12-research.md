# Research Note: Predicting User Locations for Proactive Route Suggestion

Date: 2026-10-12
Goal: Detect recurring patterns in location data (e.g., "every Thursday 15:15 drive to music school with the kid") to predict user destinations and proactively suggest routes.

## 1. Reference publication

**Song, Qu, Blumm, Barabási — "Limits of Predictability in Human Mobility", Science 327, 1018 (2010)** (`research/Limits of Predictability in Human mobility.pdf`)

Key methodology:
- Data: anonymized mobile phone records, 50,000 users, 3 months, tower-level locations (~3 km² reception areas), hourly sequences; users filtered to >2 distinct locations and call frequency f ≥ 0.5/hour.
- **Mobility network** (this is already a graph!): per-user directed graph, nodes = visited locations (size = % time spent), edges = observed movements.
- Three per-user entropy measures:
  1. Random entropy: `S_rand = log2(N)` (N distinct locations)
  2. Temporal-uncorrelated entropy: `S_unc = -Σ p(j) log2 p(j)` (visitation frequencies)
  3. Actual entropy `S`: includes order of visits + time spent (full spatiotemporal order); estimated via probabilities of time-ordered subsequences (Lempel-Ziv estimator, SOM section S4)
  - Property: `S ≤ S_unc ≤ S_rand`
- **Fano's inequality** converts entropy into an upper bound on predictability Π (probability of correctly predicting the next location, for ANY algorithm).
- Missing-data handling: q = fraction of hourly intervals with unknown location (median q ≈ 0.7 in their data); they study S(q) dependence.
- Key result: **93% average potential predictability**; Π > 0.7 for 93% of users; predictability largely independent of mobility range (distance covered).

Implication for us: human mobility is highly predictable IF we capture the temporal order (actual entropy ≪ uncorrelated entropy) — justifies sequence-based and routine-based models. Reproducing this analysis on GeoLife gives us a per-user predictability ceiling to sanity-check our predictors.

## 3. Methods landscape (state of the art)

### 3.1 Preprocessing / spatial discretization
- **Stay-point (stop) detection** — Zheng et al. 2009 (GeoLife authors): group consecutive points within ~200–300 m radius for ≥ 5–20 min → semantic place. Then trips = movements between stays.
- **Uber H3** hierarchical hexagonal grid:
  - res 6 ≈ 36 km², res 7 ≈ 5.2 km², res 8 ≈ 0.74 km², res 9 ≈ 0.10 km² (average hex areas)
  - uniform cell areas, exact neighbor rings (k-ring), parent/child hierarchy across resolutions
  - Plan: res 8 for stops, res 6–7 for movement corridors; parent mapping gives multi-scale views.
  - Python: `h3` package (v4: `latlng_to_cell`, `cell_to_parent`, `grid_disk`, ...)

### 3.2 Predictability analysis (paper reproduction)
- Hourly-binned location sequence per user → `S_rand`, `S_unc`, actual entropy via **Kontoyiannis/Lempel-Ziv estimator** → Fano → Π per user.
- GeoLife is GPS (complete while logging) but has long gaps (device off) — adapt the paper's `q` (unknown-interval fraction) treatment.

### 3.3 Statistical baselines
- Time-conditioned frequency predictor: most-visited cell given hour-of-week.
- **Order-k Markov chains** over H3 cells (k=1,2,3); individual (per-user) vs collective (all users). Song et al. 2004 ("Evaluating location predictors", HP Labs) showed low-order Markov is a strong, hard-to-beat baseline.
- Backoff/smoothing for unseen transitions.

### 3.4 Routine / periodic pattern mining (the "Thursday 15:15" detector)
- Periodic pattern mining in trajectory data (Li et al., KDD 2005 "Mining periodic patterns"); calendar-based (day-of-week × time-bucket) origin→destination profiles.
- Output: `(origin cluster, dest cluster, weekday, time window, support, confidence, stability-across-weeks)` tuples → routine cards → trigger rule: P(dest | now, recent context) ≥ threshold → suggest route.
- Time buckets: 15-min for trigger precision; hour-of-week for stability.

### 3.5 Deep learning for next-location
- **DeepMove** (Feng et al., KDD 2018): attention over historical trajectories + RNN — canonical strong baseline.
- Transformers for mobility (MobGT — Mobility Graph Transformer, Xu et al. 2023; others).
- **GNN-based next-POI recommendation** — survey: Yu et al. 2024 (Springer); POI-POI transition graphs, user-POI bipartite graphs, spatial proximity graphs; POI-RGNN (Capanema et al. 2023).

### 3.6 Graphs — verdict: YES, useful in three distinct ways
1. **Per-user H3 transition graph** (exactly the paper's mobility network): nodes = H3 cells (dwell stats), directed weighted edges = transitions (counts + time-of-day histograms). Interpretable — routine edges can be shown/explained to the user. Enables random-walk predictors, home/work inference (dwell × hour-of-week), community detection, centrality.
2. **Input to GNNs** for next-POI prediction (transition graph + temporal features, GCN/GAT + sequence head — "MobGT-lite").
3. **Road graph for routing itself** (OSM via OSRM/Valhalla/OSMnx) — destination prediction → route is a graph shortest-path problem.

### 3.7 Route generation
- **OSRM** (local docker on Beijing OSM extract) — fast car routing; fallback: OSRM public demo server (rate-limited) or Valhalla/GraphHopper.
- Map predicted origin/dest cell centroids → snap to road → route → folium/kepler visualization.
